# The Offline-Divergence Sweep

This document explains what the divergence sweep measures and defines the terms
the orchestrator code uses. Read it before reading
[`crates/orchestrator/src/partition_heal.rs`](../crates/orchestrator/src/partition_heal.rs)
or [`crates/orchestrator/src/contention.rs`](../crates/orchestrator/src/contention.rs).

## The experiment in one paragraph

Two replicas hold the same document. They lose contact with each other. Each one
keeps editing on its own for a while. They then reconnect and merge. The sweep
measures **how long that merge takes**, and it repeats the measurement across a
range of workloads. The interesting question is not how long any single merge
takes. It is how the merge cost changes as the workload changes, and whether the
CRDT libraries differ from each other in how they respond.

## Why this workload

A CRDT library is normally exercised online, where replicas sync constantly and
very few operations are concurrent. The offline case is different. A replica
that edits for hours or days without contact accumulates a large batch of
operations that are all concurrent with the other side's batch. That batch is
what the merge has to reconcile.

A widely repeated claim holds that the production libraries perform the same as
each other, except possibly on conflict-heavy workloads, which are said to be
rare. This sweep tests that exception directly: it generates the conflict-heavy
workloads on purpose and measures whether the libraries stay equivalent.

## Grid and cell

A **cell** is one fully specified experiment. It fixes every workload setting.

A **grid** is the set of cells produced by combining the swept settings. The
current grid has two axes:

| | `append` | `random_position` | `same_region` |
|---|---|---|---|
| **10² ops/side** | cell | cell | cell |
| **10³ ops/side** | cell | cell | cell |
| **10⁴ ops/side** | cell | cell | cell |
| **10⁵ ops/side** | cell | cell | cell |

4 sizes × 3 localities = **12 cells**. Six control cells start from an empty
document. See [The shared starting document](#the-shared-starting-document). Each one is a TOML file in
[`scenarios/`](../scenarios/), generated by
[`scenarios/gen-divergence-grid.py`](../scenarios/gen-divergence-grid.py). The
files are generated rather than hand-written so that a cell's filename, its
`name` field, and its `ops_per_group` value cannot drift apart. A mismatch there
would look like a real result rather than a typo.

Settings that are held constant across the grid are still part of a cell. They
are recorded in each run's provenance file, so a cell fully describes its own
workload. If a constant is later swept, it becomes a new axis.

## The two axes

### Divergence volume — `ops_per_group`

How many operations each replica applies while cut off. Swept over 10², 10³,
10⁴, and 10⁵. This axis controls **how much** concurrent history the merge has
to reconcile.

### Edit locality — `locality`

Where each insert lands. This axis controls **how much of that history actually
conflicts**.

The distinction matters, and it is the least obvious idea in the sweep. Two
replicas editing the same document is not by itself a conflict. A conflict is
two replicas attaching a new element to *the same existing element* while cut
off from each other. When they reconnect, the merge must decide which one comes
first, and it must make that decision consistently on both sides.

| Variant | Rule | Contention produced |
|---|---|---|
| `append` | insert at the end (`pos = len`) | Only the seam where the two runs join. Two siblings, at any cell size. |
| `random_position` | insert at a uniformly random position | An insert can attach to any character of the shared starting document (see below), so the conflicts are many and small. They grow roughly with the square of the operations per side. |
| `same_region` | insert at position 0, always | Every operation contests the same anchor. Contention equals the total operation count. |

At 10⁴ operations per side, `append` has 2 concurrent siblings and `same_region`
has 20,000, all on one anchor. `random_position` has about 1,660 contested
operations, spread over about 790 characters.

### The shared starting document

Before 2026-11-07, every cell started from an empty document. The two replicas
then shared only HEAD, so `random_position` contested almost nothing: about 18 of
20,000 operations at 10⁴ per side. It was not a middle level of conflict.

Each main-grid cell now starts from the LaTeX paper of crdt-benchmarks B4, with its
full edit history: 259,778 transactions that leave 104,852 characters. All three
localities start from it, so the locality axis changes only the shape of the
conflict, and not the size or history of the document.
The orchestrator replays the trace once on replica 0, and each trial loads the
encoded document on every replica before the clock starts. The replicas then share
the characters of the paper, and a random insert on each side can attach to the
same one. For `random_position`, the amount of conflict depends on the operations
per side:

| Ops per side | Contested operations | Contested characters |
|---|---|---|
| 10² | about 0.7 (0.3%) | 0 to 1 |
| 10³ | about 23 (1.2%) | about 12 |
| 10⁴ | about 1,660 (8.3%) | about 790 |
| 10⁵ | about 68,600 (34%) | about 24,900 |

These are the means over three repetitions, from the contention model. The paper
does not change the conflict of the other two localities. `append` contests only the
seam after the last character of the paper, and `same_region` puts every insert on
HEAD, as with an empty start. The trace file must be in `traces/`. See
[replay.md](replay.md#quick-start).

**Control cells.** Six cells start from an empty document:
`divergence-n2-<locality>-empty-1e3` and `-1e4`. Compare each one with the main-grid
cell of the same locality and size, to see what the size and history of the starting
document alone cost.

## Phases of one trial

Run by
[`run_partition_heal`](../crates/orchestrator/src/partition_heal.rs):

1. **Setup.** Reset every replica. If the cell has a baseline, load it on every
   replica, and check that all replicas hold the same document. For text
   workloads, create the shared text object on every replica. Wire the
   *complete* post-heal graph with every link open, and wait until the sync on
   every link is idle. Then block every cross-group link. A blocked link stays
   open but carries no data, and it keeps its sync state.
2. **Divergence.** Each group applies `ops_per_group` operations. The blocks
   keep the groups invisible to each other.
3. **Gate.** Confirm that the groups really did diverge.
4. **Heal.** Clear the blocks and kick the sync. Each side still has its sync
   state from before the partition, so it sends only what changed. **The clock
   runs from the first unblock until every replica reports the same
   fingerprint.**
5. **Gate.** Confirm the merged document contains both sides' work. Its length
   must equal the baseline length plus the operation count.

**The sync before the partition.** Sync is idle when no replica has a message to
send, and every message that a replica sent has arrived. The orchestrator checks
both with the `SyncPending` and `GetStats` calls. A timer cannot show this, because
an Automerge replica can compute for hundreds of milliseconds between two messages
of one handshake. The heal then measures a reconnect, not a first contact. See
[`metrics.md`](metrics.md).

**The sync protocols.** Automerge has its own sync protocol. Yrs and Loro have none,
so their adapters add one that follows the Yjs sync protocol: each side sends its
state vector or version vector, and the other side answers with what that version
lacks. Before 2026-11-07, these adapters sent data based only on what they had sent
before, so after a reset they sent the whole document.

Setup happens before the clock starts on purpose. Opening a sync stream costs a
TCP connect and an HTTP/2 handshake, and that cost grows with the number of
links opened. An earlier version of the harness opened links at heal time, which
meant a full-mesh heal paid the cost on every cross-group pair while a bridge
heal paid it once — so comparing the two compared connection setup as much as
merge cost. On the docker lane that setup was up to 70% of the measured window.
See [`docs/metrics.md`](metrics.md#wiring_ms-the-residual-setup-inside-the-window).

## What is measured

- `convergence_ms` — time from the first unblock to global agreement. This is
  the sweep's main result.
- `wiring_ms` — the part of that window spent clearing the blocks. It is
  reported separately so it can be checked, and it doubles as a host-noise
  signal.

## Validity gates

These are checks, not measurements. They run outside the timed window. They
exist because a broken experiment produces clean-looking numbers.

| Gate | What it catches |
|---|---|
| `verify_groups_diverged` | The partition leaked. The groups already agreed, so the heal measured nothing. |
| `verify_text_length` | The merge discarded one side's work instead of interleaving it. Operations are insert-only and one character each, so the final length must equal the total operation count. |
| Achieved contention ([`contention.rs`](../crates/orchestrator/src/contention.rs)) | The locality axis did not produce the contention it claims to. |
| `replicant.sync.messages.deferred` | A flush was skipped because the peer's outbound channel was full. It should be zero. A docker run is only trustworthy when the provenance file reports `deferred_total` of 0 and a non-zero `tx_total`. |

The gates outrank the statistics. The largest error found in this project so far
was a 7–21× overstatement of the bridge-heal advantage, and it was **bias, not
variance** — no confidence interval would have caught it. A gate did.

## Achieved contention

[`contention.rs`](../crates/orchestrator/src/contention.rs) answers one
question: *did the locality knob do what it claims?* It runs no CRDT. It replays
the same seeded position draws the runner will use and counts how many
operations end up contesting a shared anchor.

The whole module reduces to counting draws at `pos == 0`, and the reason is
worth stating plainly:

> Both replicas start from an empty document and never sync during the
> divergence phase. Every element identity is therefore created by one replica
> and visible only to that replica. No identity from replica A can ever be an
> anchor for replica B. HEAD is the only identity they share, so HEAD is the
> only anchor that can be contested.

That argument only holds for singleton groups. In a multi-node group the
replicas sync with each other during the partition, identities do cross
replicas, and the shortcut fails. `simulate` returns `None` there instead of
guessing.

Because the argument is load-bearing, `simulate_general` implements the slow,
general version — it builds both sequences and finds contested anchors directly
— and a test requires the two implementations to agree.

With a baseline, the replicas share every character of the starting document, so
the shortcut does not hold. [`contention.rs`](../crates/orchestrator/src/contention.rs)
then tracks which character each position names, and counts the inserts on each
shared character. A test requires the result to agree with the plain reference
simulation. The provenance file reports `contested_anchors`, `contested_ops`, and
`max_concurrent_siblings`, each as the minimum, maximum, and mean over the
repetitions.

## Comparing libraries

The comparison is **not** a ranking. A ranking only changes when two curves
cross, so two libraries could go from 1.01× apart to 8× apart with no change in
rank at all. Testing the order would under-test the claim.

The unit of comparison is the **pairwise ratio of merge times, per cell**. The
same frozen workload is replayed against each library, and each cell yields a
ratio. The claim under test says that ratio stays near 1 everywhere. The result
of the sweep is the *shape* of the ratio surface across the grid: where the
libraries separate, where they are equivalent, and where the data cannot say.

Equivalence needs a positive test. Failing to reject "no difference" is not the
same as sameness, since it is equally consistent with a noisy experiment.

## Reproducibility

Every operation stream comes from a seeded PRNG:

```
seed = f(cell, replica, repetition)
```

Implemented as `seed_for`, over the hand-rolled `SplitMix64`, both in
[`workload.rs`](../crates/orchestrator/src/workload.rs). The PRNG is hand-rolled
so the workload does not depend on an external crate keeping its algorithm
stable across versions.

Two replicas draw different streams. The same three inputs always replay the
same stream. Repetitions within a cell vary the seed, which is what produces the
run-to-run variance estimate. Cross-library comparisons hold the workload fixed,
so a difference between libraries cannot be sampling noise.

Seeds and cell parameters are written to the provenance file before the first
trial, so an interrupted sweep still leaves a record of what it was running.

## Current scope and limits

State these when reporting results. They are choices, not oversights.

- **Two replicas.** This isolates the merge with no topology confound. More
  replicas is future work.
- **One starting document.** Every main-grid cell starts from the B4 paper, so
  its baseline length and history depth are fixed at that one document. The
  control cells give a second point, an empty document. Neither is a swept axis
  yet.
- **Insert-only, one character per operation.** No deletes, so no tombstones.
  Visible length, history depth, and operations-per-side are currently the same
  number in all 12 cells.
- **Content is filler.** Merge cost depends on position, operation type,
  operation count, and replica — not on what the characters are. Content matters
  only for the storage metric, through compression, so it is held constant.

## Glossary

| Term | Meaning |
|---|---|
| **Site / replica** | One independent copy of the document. Generates operations locally with no coordination and owns a unique ID. That ID is part of every element's identity and breaks ties between concurrent inserts, so it affects merge results and not just routing. |
| **Cell** | One fully specified experiment: a fixed value for every workload setting. |
| **Grid** | The set of cells formed by combining the swept settings. |
| **Axis** | One setting that is swept across the grid. Currently `ops_per_group` and `locality`. |
| **Divergence phase** | The interval during which the groups are cut off and editing independently. |
| **Heal** | Reconnecting the groups. The measured window. |
| **Anchor** | The identity of the existing element that a new insert attaches to. An insert at position `p` anchors to the identity at `p - 1`; an insert at position 0 anchors to HEAD. |
| **HEAD** | The sentinel identity at the start of a sequence. It exists before any element does, so it is the only anchor two replicas of an empty document both know. |
| **Contested anchor** | An anchor that received inserts from more than one replica while those replicas were out of contact. |
| **Concurrent siblings** | The set of inserts attached to one contested anchor. Ordering them is the merge work. |
| **Seam** | The single contested anchor produced by `append`, where the two replicas' runs of inserts join. |
| **Intended contention** | What a `Locality` variant claims it produces. |
| **Achieved contention** | What the generated stream actually produces, as measured by `contention.rs`. |
| **Repetition** | One re-run of the same cell with a different seed. The source of the run-to-run variance estimate. |

## Recorded observations

Dated findings. These are results, not specifications — do not treat them as
guarantees of current behaviour.

**2026-08-06 — the shared text object is what makes locality reach the CRDT.**
A standalone Automerge 0.9 probe at 10⁴ operations per side. With each replica
creating its own text object, all three localities merged in about 70–78 ms and
were indistinguishable. With a shared base object, `append` / `random_position`
/ `same_region` merged in 73 / 90 / 208 ms. Contention is a real cost driver
once the experiment is wired correctly, and it is invisible when it is not.
`same_region` cost about 2.9× `append`. This is the finding behind the
precondition documented on `Locality`.

**2026-08-07 — `wiring_ms` is a host-noise channel.** An anomaly in the
`same_region-1e2` cell turned out to be host noise rather than CRDT behaviour,
and `wiring_ms` was what identified it.
